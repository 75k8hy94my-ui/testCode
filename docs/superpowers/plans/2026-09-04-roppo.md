# 六法 Feature Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a vault-gated legal-code reader with e-Gov statute loading, search, per-article notes, favorites, and home/navigation entry points.

**Architecture:** `roppo-data.js` contains the law catalog, pure state/search helpers, and XML parsing. `roppo.html` owns authenticated UI and fetches current statute XML from e-Gov at runtime. User state is included in the existing monolithic encrypted Vault through `vault-payload.js` and in portable backups through `backup-format.js`.

**Tech Stack:** Static HTML/CSS/JavaScript, Node 22 `node:test`, existing MangaVault/Vault payload APIs, e-Gov Law API v1.

**Spec:** `docs/superpowers/specs/2026-09-04-roppo-design.md`

## Global Constraints
- Static HTML/CSS/JavaScript only; no production dependencies or build step.
- Never persist statute text in the encrypted user state.
- 六法 user data must travel only through the existing encrypted Vault payload.
- `npm test` and `npm run verify:static` must pass before merge.
