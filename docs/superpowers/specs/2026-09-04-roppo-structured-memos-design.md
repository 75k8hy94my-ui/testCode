# 六法・構造化メモ設計

## 目的

六法の各項に対する自由記述メモを廃止し、学習用途に適した「要件・効果・定義・趣旨」の4分類で記録できるようにする。さらに、六法ページ上部の表示設定で各分類を一括表示・非表示でき、その設定を以後閲覧するすべての法律・条文・項へ共通適用する。

## 対象

- `roppo.html`
- `roppo-data.js`
- 六法状態のVault同期・バックアップに使われる既存 `mangaReaderRoppoState`
- 関連テスト

法令JSON、法令同期処理、お気に入り、最近見た条文、検索挙動は変更しない。

## メモのデータ構造

状態スキーマを更新し、各項のメモを1つの `text` ではなく4フィールドで保存する。

```js
notes: {
  "<lawId>|<articleKey>|P_<paragraph>": {
    requirements: "要件の記述",
    effects: "効果の記述",
    definitions: "定義の記述",
    purpose: "趣旨の記述",
    updatedAt: "ISO-8601"
  }
}
```

空文字のフィールドは保存時に保持してもよいが、4フィールドすべてが空ならその項の `notes` エントリ自体を削除する。

ユーザー確認により現行自由記述メモの移行は不要。旧 `note.text` は新スキーマへの正規化時に破棄してよい。

## 表示設定

`preferences` に全六法共通の表示設定を保存する。

```js
preferences: {
  selectedGroup: "...",
  selectedLawId: "...",
  memoVisibility: {
    requirements: true,
    effects: true,
    definitions: true,
    purpose: true
  }
}
```

初期値は4項目すべて表示。設定は法律・条文・項ごとではなく、ユーザーの六法全体に対するグローバル設定として扱う。既存のVault同期対象である `mangaReaderRoppoState` に含まれるため、別ストレージは増やさない。

## UI

六法ページ上部、分野・法令・検索コントロールより上または同じコントロールパネル上部に「メモ表示」を置く。

- 要件
- 効果
- 定義
- 趣旨

の4つをトグル式のチップ／ボタンで切り替える。ON/OFFは視覚的に明確に区別し、タップ領域はモバイルでも十分な大きさを確保する。

各項カードのメモ領域には、ONになっている分類だけを縦に表示する。それぞれにラベルと独立した入力欄を持たせる。例:

- 要件
  - textarea
- 効果
  - textarea
- 定義
  - textarea
- 趣旨
  - textarea

非表示にした分類はDOM上で入力欄を表示しない。ただし保存済み内容は削除しない。再度ONにすると内容をそのまま復元表示する。

4分類すべてOFFの場合は、その項のメモ領域自体を折りたたみ、条文本文だけを表示する。

## 保存挙動

現在と同じく入力を短いデバウンス後にローカル保存し、既存Vault同期をスケジュールする。

- 1フィールドの変更で、その項の4分類をまとめたnoteオブジェクトを更新する。
- `updatedAt` は最後にいずれかの分類を変更した時刻。
- すべて空になった項はnotesから削除する。
- 表示設定変更も即ローカル保存し、Vault同期対象とする。

## スキーマと正規化

`roppo-data.js` の `DEFAULT_STATE` と `normalizeState` を更新する。

- 新スキーマは `schemaVersion: 3` とする。
- 新形式のnoteだけ正規化して保持する。
- 旧形式の `{text, updatedAt}` は今回は破棄する。
- `memoVisibility` が欠落・不正な場合は4項目すべて `true` に補完する。
- 既存のお気に入り、recent、selectedGroup、selectedLawId はそのまま正規化・維持する。

## PC・モバイル

PCとモバイルで機能は共通。モバイルでは4つの表示切替を2列×2行または折り返し可能なチップ群にし、横スクロールを要求しない。

各メモ欄は1列で縦に並べ、入力欄の高さは自由記述1欄時より小さめから開始して、必要に応じて伸ばせるようにする。4項目すべて表示しても項カードが過度に巨大化しないことを優先する。

## テスト

最低限、以下を自動テストする。

1. `normalizeState` が4分類メモを保持する。
2. 旧 `text` メモを破棄する。
3. `memoVisibility` の既定値が4項目すべてONになる。
4. 表示設定が保存・再読込で維持される。
5. `roppo.html` に4分類の表示切替UIが存在する。
6. 非表示設定が各項のメモ欄描画へ反映される。
7. 4分類すべて空ならnoteを削除する処理がある。
8. 既存Vault同期・バックアップのround-tripテストが新スキーマでも通る。
9. 既存の検索、項ごとのメモキー、お気に入り、モバイル一覧のテストが退行しない。

## 非対象

- 要件・効果・定義・趣旨の自動生成
- AIによる既存文章の分類
- 分類項目のユーザー追加・名称変更
- 法律ごと／条文ごとの表示設定
- 旧自由記述メモの移行UI
