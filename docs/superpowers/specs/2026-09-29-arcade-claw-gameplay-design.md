# 駅前ゲームセンターとクレーンゲーム — 設計仕様

## 目的

若葉駅前に遊びに行ける小さなゲームセンターを追加し、所持金を使う実操作型クレーンゲームと、獲得した景品のコレクションを提供する。既存の施設メニューだけで完結する活動とは異なり、タイミングと位置をプレイヤー自身が操作する。

## 採用範囲

- 若葉駅北東の商店街に「若葉ゲームコーナー」を追加する。広場から歩道網を経由して到達できる。
- 1種類のクレーン筐体を実装する。画面上で左右移動し、決定操作でクレーンを降ろす。停止位置と景品配置に基づき、成功または失敗を決定する。
- 料金は1プレイ¥300。プレイ開始時に支払い、資金不足なら開始不可。報酬の現金化は不可。
- 景品は6種類。獲得済み一覧、プレイ回数、獲得数を保存する。同じ景品の重複取得も可能で、コレクションは種類と個数を表示する。
- キーボード（左右矢印/A・D、Enter/Space）とタッチ操作に対応。狭い画面でもゲーム画面、説明、操作ボタンが利用可能。
- 記録・景品は既存セーブスナップショットへ追加し、旧セーブは空のコレクションに移行する。

## 体験とルール

施設で「クレーンゲーム（¥300）」を選ぶと、通常の行動メニューからゲーム画面に切り替わる。ゲーム中は左右入力でクレーンを移動し、決定入力で1回だけ落下を実行する。筐体には複数の景品が描かれ、各景品に対応する取得可能範囲が視覚的にわかる。判定はモデル側で停止位置・配置・乱数入力から決まり、UI演出に結果判定を委ねない。終了後は獲得品または惜敗を表示し、「もう1回」「景品を見る」「戻る」を選べる。再プレイのたびに再度料金を確認・徴収する。

狙いを外しても時間を不必要に消費させず、1プレイにゲーム内5分を進める。現金や景品を増殖させる再送・連打経路を作らない。運の要素は残すが、操作位置が成功確率に影響する。

## 状態とインターフェース

新規の依存なしのUMD/CommonJSモデル `game/arcade-games.js` を作る。カタログ、初期状態、正規化、開始時の支払い検証、プレイ解決、景品一覧を提供する。ゲーム側の状態は `state.arcade` とし、最低限 `plays`, `wins`, `prizes`（ID別個数）を持つ。モデルは不正な座標・金額・乱数値を安全に拒否し、UIの一回の解決につき一度だけ結果を返す。停止位置から景品を選ぶため、存在しない景品IDを受け付けるAPIは設けない。

マップ追加は既存の `map-model.js` に施設・入口・歩行者専用接続を追加し、徒歩接続検証を維持する。`game.js` は施設メニュー、専用ミニゲーム状態・描画・入力、保存/復元、ローカルテスト用スナップショットを統合する。ゲームモード中に通常移動・施設再操作が二重発火しないこと。

## 視覚・操作

マップ上では駅前の小型ネオン看板付きゲームコーナーとして識別できる。ミニゲームは既存Canvasのゲーム世界とは分離したDOMオーバーレイ内に専用Canvasを置き、キーボード・タッチの双方から同じモデル呼び出しを使う。タッチには「左」「右」「つかむ」を置き、キーボードの案内も併記する。フォーカス、Esc/戻る操作、ページ再描画を含め終了時に入力リスナーを残さない。

## 非対象

複数筐体、アーケード景品の販売・交換、ランキング/オンライン同期、サウンド素材制作、課金や新規依存の導入は行わない。`game/character-showcase.html`は別セッションのローカル検証用であり、変更・コミット・pushのすべてから除外する。

## 受け入れ条件

1. 新施設へ徒歩で到達でき、地図上で施設として表示される。
2. ¥300未満では開始せず、開始時に正確に¥300が差し引かれる。
3. 操作位置が成功判定に影響し、1プレイにつき結果と5分経過が一度だけ適用される。
4. 6種の景品の獲得・重複・表示と、プレイ/獲得記録が再読込後も維持される。旧スナップショットも復元可能。
5. キーボードとタッチの両方で開始、操作、結果確認、終了ができる。
6. `npm test` と `npm run verify:static` が成功し、headless ChromiumでPC・モバイルの画面を確認する。console error/warning、pageerror、failed request、bad responseを検査し、修正後にも撮影する。
