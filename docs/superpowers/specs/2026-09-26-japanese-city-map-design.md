# City Days 日本風都市マップ設計

## 目的

現在の `game/game.js` は、`ROAD_GAP` を基準にした格子道路と区間単位の小さな曲線で街を生成している。そのため、画面上では格子状の区画に人工的な曲線を足した状態に見え、日本の都市に見られる幹線道路、T字路、細街路、袋小路、商店街、公園周辺の不規則な街区が表現できていない。

本変更では、道路の見た目だけを変更せず、描画・衝突判定・徒歩移動・車の経路探索・交通信号・建物配置・施設入口・ミニマップが同じ地図データを参照する構造へ移行する。対象はゲーム内の架空都市であり、特定の実在都市や道路形状をそのまま再現しない。

## 成功条件

- ゲーム画面が格子状ではなく、複数の道路階層と不規則な街区を持つ日本風の都市として見える。
- 自宅、カフェ、スーパー、公園、ジム、図書館、駅の各施設へ徒歩・車で到達できる。
- 道路、歩道、建物、施設入口、ミニマップの位置が同じ地図モデルから導出される。
- 徒歩の当たり判定、車の経路探索、交通信号、交通車両、保存済み車両の移行が新マップで破綻しない。
- 既存セーブを読み込んでもゲームが黒画面や例外で停止しない。
- `npm test`、`npm run verify:static`、ローカルブラウザでの初期表示・操作・保存・再読み込み確認が成功する。

## 採用アーキテクチャ

### MapModel

`game/map-model.js` を新設し、以下の不変データと幾何ヘルパーを提供する。

- `WORLD_SIZE`、海岸境界、鉄道位置
- 地区定義：駅前商業地、住宅地、商店街、公園・神社、周縁部
- 道路ノード：安定した `id`、ワールド座標、交差点種別、信号の有無
- 道路エッジ：`id`、始点・終点、ポリライン、幅、道路種別、制限速度、車両通行可否、歩行可否、方向属性
- 歩道・緑道：歩行専用ポリラインと幅
- 区画：道路沿いの建築可能ポリゴンまたは矩形近似、用途、建物密度
- 施設入口：施設ID、入口座標、接続する歩道ノード、接続する車道ノード
- 駅入口：既存の駅システムが利用する入口座標と最寄り歩道

マップの形状は手続き的な乱数で毎回変えず、固定ブループリントとして定義する。これにより、保存データ、テスト、経路探索、画面確認が再現可能になる。描画用の装飾乱数は既存の `hash2` を利用してもよいが、道路接続性や施設座標を変えてはならない。

### 地区と道路の設計

- 駅前商業地：駅から伸びる商店街、歩行者優先道路、短い街区、複数のT字路
- 住宅地：曲率の異なる生活道路、袋小路、細い通り、斜めの接続、住宅の小区画
- 公園・神社：大きな緑地、外周道路、緑道、神社への参道、車両通行止めの歩行路
- 幹線道路：都市を横断する少数の道路。交差点と信号を限定し、現在の不自然な大きな曲線は使わない
- 周縁部：海岸・空き地・工業的な区画を配置し、都市中心部と明確に区別する

幹線道路は長いポリライン、生活道路は複数の短いポリラインとして定義する。隣接するエッジの終点は同一ノード座標を共有し、描画上の隙間と経路探索上の断線を防ぐ。曲線はベジェ曲線を区間ごとに足すのではなく、地図ブループリントのポリライン頂点を通る滑らかな補間として必要な箇所に限定する。

### 既存システムとの接続

`game/game.js` は地図データの所有者ではなく、MapModelのAPIを利用する。

- `roadEdgeExists`、`roadNeighbors`、`isSignalizedIntersection`：MapModelのノード・エッジ検索へ置換
- `roadEdgePoint`、`roadDistanceToEdge`、`nearestRoadSegmentInfo`：ポリライン最近傍点APIへ置換
- `isRoad`、`canStand`：道路エッジ幅、歩道、建物区画を共通の衝突問い合わせで使用
- ルート探索：格子座標の隣接探索を道路ノード・エッジのグラフ探索へ置換。車両不可の歩道は車ルートから除外する
- `buildLanePath`：道路エッジの中心線と車線オフセットから生成。交差点での停止線・信号方向もエッジ属性から決定
- `generateBuildings`：区画定義から建物を生成。特殊施設は施設入口と区画を固定し、既存の施設IDを維持
- `drawSparseRoadNetwork`、`drawNeighborhoodGround`：可視範囲にあるMapModelのエッジ・区画だけを描画
- ミニマップ：道路エッジ、駅、施設、プレイヤーをMapModelから描画
- 地区名：格子の割合ではなく、MapModelの地区ポリゴンまたは地区IDから判定

### 施設と既存セーブ

既存の施設ID (`home`、`cafe`、`store`、`park`、`gym`、`library`) と保存形式は維持する。施設オブジェクトの座標はブループリントの入口から初期化する。

既存セーブを読み込む際は、次の順序で安全に移行する。

1. 既存のプレイヤー座標を読み込む。
2. その座標が歩行可能なら維持する。
3. 建物内部、海岸外、旧道路上など歩行不能なら自宅入口の安全地点へ移動する。
4. 保存済み車両がある場合は、最近傍の車両通行可能エッジへ投影する。
5. 投影先が見つからない場合は自宅近くの車道上に配置し、速度・ルート・目的地を初期化する。

新しいセーブにはマップバージョンを追加してもよいが、既存の `testCodeLifeSimSave:v1` の読み込みを壊さない。将来マップを再変更する場合に備えて `mapVersion` は保存時に書き込み、未知のバージョンは安全な初期位置へフォールバックする。

## エラー処理

- MapModelの検証関数は、重複ID、孤立した施設入口、存在しないノード参照、異常な道路幅、施設へ到達不能なグラフを検出する。
- 初期化時に検証エラーがあれば、Canvasを黙って黒画面にせず、既存の `.game-runtime-error` に原因を表示する。
- ルートが見つからない場合は既存の目的地選択UIを閉じず、ユーザーに再選択可能な状態を残す。
- マップデータは外部ファイルやネットワークに依存せず、ローカル静的ファイルとして読み込める形にする。

## テスト方針

先にMapModelのテストを追加し、以下を固定する。

- 全道路エッジの始点・終点が有効なノードを参照する。
- 主要施設と駅が歩行グラフから到達可能である。
- 車両目的地間に車道だけのルートが存在する。
- 道路の最近傍問い合わせが正しいエッジと距離を返す。
- 道路幅・区画・歩道の衝突判定が期待どおりである。
- ミニマップがMapModelの道路数・施設数と一致する。
- 旧形式のセーブ座標が安全に読み込まれる。

実ブラウザでは `http://localhost:5173/game/` を使用し、次を確認する。

- 初期画面に黒画面、描画停止、Console例外、読み込み失敗がない。
- マップ全体を徒歩移動して、道路・建物・施設の境界が不自然に途切れない。
- 操作パネル、施設利用、車への乗車、目的地選択、信号表示、保存、再読み込みが動作する。
- 画面を移動してもミニマップと地区名が実際の位置に追随する。

## スコープ外

- 実在都市の道路を取得・再現すること
- 外部地図API、地理データ、ネットワーク接続の導入
- ゲームルール、通貨、ニーズ、施設アクションの仕様変更
- 車両モデルやキャラクター描画の全面的な作り直し
