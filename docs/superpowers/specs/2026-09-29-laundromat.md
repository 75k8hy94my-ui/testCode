# コインランドリー機能

## 目的

生活ゲームに、服の手入れを計画して街の施設を使う継続的な生活ループを追加する。プレイヤーが着ている服は生活時間に応じて汚れ、街のコインランドリーで料金と時間を使って洗濯できる。既存の身体の衛生度とは独立した衣類の状態とする。

## 現状と制約

- アプリはビルド工程・本番依存のない静的 HTML/CSS/JavaScript。
- 服の所持・着替え・カタログは `game/wardrobe.js`、操作UIとゲーム時間・スナップショットは `game/game.js`。
- 施設と歩行接続は `game/map-model.js` にある。新施設には歩行者用の入口接続が必要。
- `game/index.html` は各モデルを読み込むため、新モデルを追加するときはゲーム本体より前にロードする。
- ゲームの生活状態はスナップショットに含め、旧セーブを安全に正規化する。
- `game/character-showcase.html` は他セッションのローカルテスト用であり、変更・ステージ・コミット・pushしない。

## ゲームループ

1. 所有している各衣装は個別の清潔度を持つ。新規衣装は清潔度100で開始する。
2. 時間経過では、現在着用中の衣装だけが汚れる。非着用衣装の清潔度は変化しない。
3. 清潔度は0〜100に制限する。身体の `needs.hygiene` には影響させず、現時点でNPC反応や能力差も追加しない。
4. クローゼットUIで、各衣装の清潔度を確認できる。着替え時間の経過中は、着替え前に着用していた衣装が汚れる。
5. コインランドリーは独立した街施設として追加し、マップ上に名称・識別記号を表示する。歩行グラフに接続し、徒歩で到達・利用できる。
6. 利用UIは現在着用中の衣装の清潔度と料金・所要時間を示す。洗濯完了時に料金を差し引き、ゲーム時間を進め、対象衣装を清潔度100にする。
7. 清潔度が既に100なら利用不可。所持金不足や営業時間外の場合も、状態・所持金・ゲーム時間を変更しない。
8. 洗濯処理は副作用を持たないモデル関数で事前検証し、成功時だけゲーム本体に状態を適用する。

## 推奨初期値

- 汚れ：着用中のゲーム内1分につき清潔度0.08減少（約20時間で0になる）。
- 洗濯：1回300円、ゲーム内30分、営業時間06:00〜23:00。
- 洗う対象：現在着用中の衣装1着。複数衣装の一括洗濯や待ち時間中の他行動は初回対象外。
- 端数はモデル内部で保持し、表示は整数に丸める。0未満・100超過は正規化時にも丸める。

値はプレイテスト後に調整可能なモデル定数とする。料金・時間を画面上に明示し、状態が変化しない理由も提示する。

## セーブ互換性とデータ整合性

- wardrobe の正規化を拡張し、所有衣装すべての清潔度を含む状態を返す。
- `wardrobe` フィールドが欠落した旧スナップショットでは、既定衣装を清潔度100で生成する。
- 不明な衣装ID・非数値・NaN・無限値は採用しない。所有していない衣装の清潔度レコードを除去する。
- 所有衣装の追加時に清潔度100の記録を追加し、着替えでは既存の各衣装の状態を維持する。
- スナップショットの保存・復元で服状態が失われない。
- 公開デバッグフックが wardrobe を直接返す場合も正規化済み・コピーを返す。

## UIとマップ

- 施設名は「若葉コインランドリー」。既存の若葉湯・住宅地に近い街区を候補とし、既存建物や道路・歩行接続と重ならない位置をマップデータから選ぶ。
- 外観は小規模な日本のコインランドリーとして既存の施設描画スタイルに合わせ、洗濯機を連想できる記号・配色を用いる。
- クローゼットでは衣装ごとに「清潔」「少し汚れ」「洗濯推奨」等の理解しやすい表示を行い、現在着用中を明確にする。
- 施設アクションは「現在の服を洗う」とし、清潔度・費用・所要時間を選択前に表示する。
- 既存のモバイル・PC操作、アクションシート、トーストのデザインに従う。

## 検証

- 純粋モデルテスト：初期値、経過時間、非着用服の不変、境界値、購入・着替え・洗濯、営業時刻、料金不足、清潔済み、破損/旧形式データ正規化。
- ランタイムテスト：スクリプト順、時間更新との接続、購入/着替えの状態維持、施設利用成功・失敗、スナップショット互換性、マップ入口接続。
- `npm test`、`npm run verify:static`、`git diff --check`。
- ローカルHTTPで起動し、CLIからPlaywright/Chromiumをheadless実行。ブラウザツールではlocalhostを開かない。PC・モバイルの画面、console error/warning、pageerror、failed request、HTTPエラーを調査し、洗濯前後とクローゼット表示のスクリーンショットを比較する。

## 今回含めないもの

- NPCの服状態・洗濯行動、服の性能/衛生ペナルティ、汚れに応じた絵柄の変更。
- 家庭用洗濯機、洗剤在庫、乾燥機の個別工程、衣装の修理・破損。
- 洗濯中に別行動を行う非同期ジョブ、一括洗濯、施設内マップ。

## 受け入れ条件

- 時間経過で着用中の服だけが再現可能な速度で汚れ、着替え後も各衣装の清潔度が保持される。
- コインランドリーがマップ上に存在し、徒歩で到達でき、状態・料金・営業時間を正しく検証して洗濯できる。
- 洗濯に成功すると服・所持金・時間が一貫して更新され、失敗時は三者とも不変。
- 旧スナップショットを含むセーブ復元で衣装状態が壊れず、全自動検証とPC/モバイルの実画面確認を通過する。
