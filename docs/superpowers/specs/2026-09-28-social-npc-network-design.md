# 会話可能NPCの関係性・行動深化 設計

## 目的

現在の街には76人の住民がいるが、個別の関係性や会話による関係変化を持つNPCはアオイ、ソラ、メイの3人に限られる。ほかの歩行者にも簡単な会話操作はあるものの、個人の生活や人間関係を感じられる会話・反応にはつながっていない。

今回は76人全員を作り込まず、10人だけを「会話可能NPC」として明確にし、相互の関係、時間帯に応じた会話・行動、プレイヤーとの会話による行動変化を追加する。既存の住民シミュレーションと移動系は維持し、その上に人物らしさを重ねる。

## 対象と目標

- アオイ、ソラ、メイの既存3人を維持し、新たに7人を加えて対象をちょうど10人にする。
- 10人それぞれに一貫した人物像、生活上の予定、会話の口調・話題を持たせる。
- 10人の間に、友人・家族・同僚・知人などの相互関係を定義する。会話や時間経過に応じた関係の変化を扱えるようにする。
- 時間帯、曜日、現在の予定、関係性、直近の会話を会話内容と行動選択へ反映する。
- プレイヤーとの会話選択によって、親密度やNPCの気分・次の行動を変える。
- 対象10人は街中で特別な視覚表示を持ち、通常住民と見分けられる。
- 既存のセーブを読み込んでも破損・初期化せず、新NPCと関係データを安全な既定値で補う。

## 非目標

- 76人全員に個別の会話、関係グラフ、専用の行動スクリプトを導入しない。
- 住民全体の経路探索や歩行ロジックをこの機能のために置き換えない。既存のNPC移動不具合は別途検証し、今回の会話機能に紛れ込ませない。
- 外部LLM、ネットワーク接続、ビルド工程、新しい本番依存を追加しない。
- 会話だけで勤務・睡眠・屋内施設などの既存スケジュール制約を無視させない。

## 対象者と識別

既存の3人は同じID・名前・セーブ上の親密度を引き継ぐ。新しい7人には決定的で安定したIDを割り当てる。10人は現在の住民プロフィール生成にひも付け、住民数76人を維持する。残る66人は現在どおり一般住民として生活シミュレーションを行う。

新規7人の名前、年齢、職業、関係性、会話上の個性は架空の若葉地区に合う内容として実装時に定義する。既存のアオイ、ソラ、メイの人物設定と相反させない。関係は片方向の表示にせず、対になる人物双方から一貫して扱う。

## 体験設計

### 街中での見分けやすさ

会話可能NPCには、人物の近くに小さな会話マークと名前を示し、既存の通常住民ラベルと区別する。既存の操作方法（近づいて会話する等）は維持し、一般住民にも残る簡易会話との違いが視覚上わかるようにする。画面上の目印はNPCの移動を隠さず、モバイルでも判別できる大きさとコントラストを保つ。

### 会話

会話開始時に、現在時刻・曜日・NPCの予定・親密度・相互関係・直近のやり取りから話題と応答を選ぶ。選択肢は少数に保ち、たとえば挨拶／近況を聞く／誘うを基本形とする。全員に同じ選択肢を出すだけでなく、人物像と状況に応じて文面や結果を変える。

会話はゲーム内時間を進め、既存の時間・ニーズ更新と整合させる。勤務中、睡眠中、急いでいるときなどは短い反応や誘いの断りがあり得る。拒否を関係の不当なペナルティにせず、理由を応答に反映する。

### 会話後の行動

会話の結果は親密度や短時間の気分・交流希望などに反映し、次の行動候補選択へ渡す。誘いを受けた場合は既存の行動計画に一時的な優先候補を設定し、受けられない場合は元の生活予定を続ける。期限切れ、予定不整合、対象施設へ到達できない場合には自然に通常の生活シミュレーションへ戻す。

親密度の変化だけで即座に遠方へテレポートさせない。行動目的地の変更は既存の経路・移動系を通じて行い、現在位置から連続して移動する。

## 行動・関係モデル

既存の時刻・曜日・ニーズ・目的地候補・移動処理を全住民の基盤として引き続き利用する。10人には、既存プロフィールとスケジュールを基にした個別の行動傾向と関係者優先度を追加する。たとえば、知人と同じ場所・時間にいるときに会話や同行候補を選びやすくする。予定とニーズの基本制約は優先される。

関係は安定した人物間の種別（家族・友人・同僚・知人など）と、変化する親密度・最近の交流状態を分ける。ペアの初期関係は一元的な定義から両者へ参照し、保存対象の可変値は同じペアについて矛盾する二重値を作らない。関係初期値は人物設定に基づき、会話のたびに不自然に急変しない範囲で更新する。

## 実装境界

- 小規模な既存の静的JavaScript構成に合わせ、会話可能NPCの固定プロフィールと関係カタログを独立モジュールとして定義する。
- `game.js` はプロフィール識別、既存会話UI、時間進行、行動候補との接続、保存・読み込みを担う。カタログ側へ描画や歩行ロジックを移さない。
- `phone-system.js` の連絡先・友人表示は同じ10人のカタログと状態を参照し、ゲーム画面とスマートフォンで別の名簿を持たない。
- 固定プロフィール、関係種別、話題定義と、セーブする親密度・短時間の行動意図を分離する。NPCの現在位置や全住民のスケジュール状態を新しい重複データとして保存しない。
- 特別NPCのIDは既存IDを保ち、住民プロフィール生成における割り当てを決定的にする。セーブデータに依存する配列順序を不用意に変更しない。

## セーブ互換性

既存セーブで保存されているアオイ、ソラ、メイの親密度を読み取れるようにする。新規7人および新規の関係データがない旧セーブでは、定義済みの初期値を使う。欠損・不正・範囲外の値は安全な既定値へ補正し、読み込み失敗やNPC全員の状態初期化を起こさない。旧形式の `friends` を読み取る互換性を保ちながら、新しい保存形式への移行方針を実装時に明示し、同じ値を二つの形式で競合させない。

## 検証と受け入れ条件

- 会話可能NPCがちょうど10人登録され、住民総数76人と残る一般住民66人が保たれる。
- 10人全員を街中で視覚的に識別でき、一般住民の簡易会話と区別できる。
- 既存3人のID・名前・親密度および現在の会話操作が維持される。
- 時間帯または曜日を変えたとき、少なくとも各人の会話内容か行動傾向のいずれかに変化が現れる。
- 関係する2人の会話・同時刻の行動が、関係性の定義に沿って一貫して扱われる。
- 受諾された誘い等が既存の移動計画に反映され、通常スケジュールへ復帰できる。予定中・拒否時・期限切れでもNPCが停止・瞬間移動・無限待機しない。
- 新旧セーブの読み込みで親密度を保持し、新NPCの状態を安全に初期化する。
- 自動テストで名簿・関係整合性・時刻別応答・行動上書きの期限・旧セーブ移行を検証する。
- `npm test` と `npm run verify:static` を実行する。ゲーム画面はCLIのheadless Playwright/Chromiumで確認し、全画面スクリーンショット、console error/warning、pageerror、failed requestを収集する。localhost確認にブラウザツールは使用しない。

## 未決定事項

名前や関係の細部は架空世界の編集上の選択肢であり、設計の必須条件ではない。実装前レビューでユーザーが変更を希望する場合は反映する。特別NPCは10人に固定し、対象を増やす場合は別途スコープを確認する。
