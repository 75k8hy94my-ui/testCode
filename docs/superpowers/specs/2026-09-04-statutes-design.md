# 六法機能 Design

## Scope

`testCode` に、憲法・民法・会社法・刑法・民事訴訟法・刑事訴訟法の6法を閲覧できる「六法」画面を追加する。商法は対象に含めず会社法を採用する。

## Statute data

法令本文はユーザーの暗号化Vaultへ入れない。e-Gov 法令APIから取得した現行法XMLをブラウザで条文単位に整形し、IndexedDB `manga-reader-statutes` に保存する。通常表示はこの端末キャッシュを使い、未取得時だけ取得する。ユーザーは選択中法令を明示的に更新できる。

## Notes

条文メモは `mangaReaderStatuteNotes` に `{ "<law-id>:<article-num>": "memo" }` の形で保存する。`vault-payload.js` の正式フィールド `statuteNotes` として既存AES-256-GCM Vaultに含め、既存CAS同期をそのまま利用する。条文本体は同期しない。

## UI

PCは条文一覧／本文と右側のメモペインを並べる。スマートフォンは条文選択時に画面下部からメモシートを表示する。法令切替、条番号・本文キーワード検索、前条・次条移動、e-Gov公式ページへのリンク、法令データ更新を提供する。メモは入力後に端末へ自動保存し、短いデバウンス後に暗号化Vaultへ同期する。デバウンス中に条文・法令・一覧を切り替える場合は、切替前に未保存入力を即時保存する。

## Navigation

ホームのデフォルトカードへ「六法」を追加する。既にカスタマイズ済みのホームには一度だけ六法カードを自動挿入し、その後ユーザーが削除した場合は再追加しない。六法画面からはホーム・索引検索・判例百選・保管庫へ移動できる。

## Failure behavior

端末キャッシュが存在する場合、e-Gov更新取得に失敗しても既存キャッシュを維持する。初回取得に失敗した場合は再試行できるエラー表示にする。メモのクラウド同期失敗時も端末保存済みメモは消さず、同期状態を表示する。

## Verification

`node --test` で法令カタログ・条番号正規化・検索・Vaultフィールド・ホームカード・未保存メモの切替前保存を検証する。`npm run verify:static` で静的HTML/JS参照を検証する。
