# MP4直リンク動画の仮想編集：段階実装

## 目的と対象

- `mangaReaderVideos` に登録済みの **HTTP(S) のMP4直リンク**だけを編集素材にする。
- 動画バイト列を取得・結合・書き換え・再エンコード・アップロードしない。
- 編集結果は「既存動画ID・再生開始秒・終了秒を並べた編集指示」として扱う。独立したMP4ファイルの書き出しは対象外。
- 既存の動画一覧・通常再生・埋め込みリンク・WebM等の動作は変えない。
- VPN/保管庫の既存のアクセス制御と同期方式を維持する。アクセス喪失時は編集用データとプレイヤーを破棄する。

## 第１段階（完了）

`video-virtual-edit.js` に副作用のない編集計算だけを追加する。

- `{ type: 'virtual-mp4-edit', version: 1, clips: [{ sourceVideoId, startSeconds, endSeconds }] }` を編集指示の形式とする。
- `sourceVideoId` は登録済み動画のID。URLを別途複製しない。
- 開始・終了はいずれも**元MP4内の絶対秒数**。終了時刻は含めない（半開区間）。
- 分割、仮想結合、区間の短縮、並べ替え、削除、総再生時間、仮想時刻から素材内時刻への対応を用意する。
- 素材存在確認とMP4直リンク形式の検査を分離して用意する。今後の保存と再生では毎回確認する。
- 編集指示を自動保存せず、動画ライブラリ/再生画面にはまだ組み込まない。既存データの移行は発生しない。

## 第２段階（完了：保存・復元の土台）

- `video-virtual-edit-store.js` を追加。登録動画一覧の中には編集版をまだ混ぜず、保護済みの `mangaReaderVideoMeta.__testCodeVirtualMp4ProjectsV1__` に独立したプロジェクトを保持する。
- 各プロジェクトはID・タイトル・編集指示・作成/更新日時・リビジョンを持つ。元動画のURLは複製せず、素材のURL変化を検出する非暗号学的指紋のみを付ける。
- `save/get/list/remove/inspect` を提供する。ソースが削除・非MP4化・URL変更されても、プロジェクトそのものは勝手に消えない。修復は後の編集画面で利用者の明示的な操作として扱う。
- 更新・削除は利用者が確認したプロジェクトリビジョンを要求する。同一端末の古い編集状態による誤上書きを拒否する。
- 既存の `vault-payload.js` とバックアップ形式は `videoMeta` の内容をそのまま同期・復元するため、新しいデータキーやクラウドテーブルは追加しない。
- 保存前のVPN/保護データアクセス確認を必須とする。同期が失敗した場合はローカル保存が残ることを明示してエラーを返す。同期競合を勝手に解決・上書きしない。
- 動画一覧の古いメタデータ書き戻しでは、より新しいプロジェクトレジストリを保持する。
- **この段階では編集画面も仮想動画の再生画面もまだ公開しない。** 本体のファイル操作は一切発生しない。

## 次の段階（各段階は独立して検証）

1. **第３段階：編集画面** — MP4動画のみから開ける編集画面を追加し、再生位置から分割、区間削除、他のMP4区間の追加、順序変更、保存を操作できるようにする。
2. **第４段階：仮想再生** — 専用プレイヤーで順番どおりの連続再生とシークを実装する。URLごとの読込失敗・通信遅延・未対応のRangeアクセスを表示し、再生の終了とVPN遮断を正しく処理する。
3. **第５段階：追加編集** — 区間複製・さらに細かいトリム等を別PRで追加する。速度変更等はブラウザ再生で確実に実現できる範囲を検証してから扱う。

## 技術上の境界

- `video-data.js` の `isDirectVideoUrl` はMP4以外も扱うので、仮想編集の素材判定には使用しない。
- `video-virtual-edit.js` はDOM・ネットワーク・localStorage・Vaultを直接扱わない。
- 第２段階以降、編集内容をVaultに追加する際は `vault-payload.js` の正規化、同期・復元経路、既存メタデータ更新による消失を個別に検証する。
- MP4のURLでも、ホストがシークに必要なHTTP Rangeをサポートしない、期限切れ、認証が必要、ブラウザのコーデックに非対応等の場合は再生に制限がある。
- 接続された２動画の境目で瞬間的な停止が起きる可能性がある。「ファイルが実際に結合される」「フレーム精度で完全に滑らかにつながる」とは保証しない。
